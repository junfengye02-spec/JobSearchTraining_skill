# 数据源策略

## 重要背景（用户提供的领域知识）

中国大陆校园招聘信息的发布路径通常是：**公司先通过自己的招聘官方微信公众号（一般名为"XX招聘"/"XX校园招聘"）发布"秋招正式启动"的推文**，推文里会附上跳转到**公司官方招聘官网/招聘系统**（如 zhaopin.xxx.com、campus.xxx.com、或第三方 SaaS 如北森/大易/Moka 搭建的官网）的链接，官网上才有完整的岗位列表和详细要求。第三方聚合平台（牛客网、猎聘校园等）上的信息大多是转载或用户自发讨论，时效性和完整度不如"公众号公告 → 官网详情"这条一手链路。

因此发现层应该把"搜索各公司招聘公众号的秋招公告"当作和聚合平台同等重要、甚至更优先的信息源，而不只是核实层的兜底手段；核实层"访问官方招聘官网"这一步也不只是给聚合平台的信息找权威链接，而是所有渠道发现的岗位都应该尽量拿到官网这个最终详情页链接。

## 发现层（并行，每次运行 4 个子 agent）

四组来源是固定的既有岗位发现主流程。若 `config.json.high_growth_company_discovery.enabled=true`，还要在这四组任务内叠加读取 [high-growth-company-discovery.md](high-growth-company-discovery.md) 的公司先行发现规则；这是增量线索，不是第五组替代来源，也不得挤占或缩减下列任何一组的岗位搜索。

按优先级排列：

1. **牛客网**（nowcoder.com）求职/校招板块 — 应届生一手讨论区，信息量最大。
2. **公司招聘微信公众号 + 官网详情**（经 WebSearch/CDP 搜索"XX招聘"公众号发布的"2026秋招/秋季校园招聘正式启动"类推文，再跳转到文中的官方招聘官网核实详细岗位）— 一手信息源，优先级高。

   > **2026-07-08 更新**：应届生求职网（yjbys.com）经实测已停用校园招聘频道（只剩简历模板/求职百科内容，历史招聘专题页返回 404/403），**不再作为数据源**，此位置替换为"公司招聘公众号+官网"。
3. **51job校园招聘**（campus.51job.com）+ **智联招聘校园**（xiaoyuan.zhaopin.com）+ **猎聘校园**（campus.liepin.com）— 结构相似，合并为一个子任务，用 `config.json` 里 `job_category_label` 的值作为频道内筛选词。
4. **门户/公众号/抖音"秋招名单/时间表"汇总贴**（经公开检索或抖音搜索发现，如搜索"{target_season_label} 名企名单"、"校招进行时 {job_category_label}"，把 config.json 里的实际值代入）+ **实习僧**（shixiseng.com）— 用于尽快发现新增开秋招的公司；抖音与其他二手来源均不得直接入表，必须回溯公司官网或官方招聘系统核实。

### 公众号线索到官网的强制追查

公众号的作用是提供“这家公司正在招聘”的发现信号，不是岗位核实页。看到公司名称后，必须继续定位公司官网的校园招聘页或其官方 ATS，并检查当前岗位列表；该义务不依赖公众号文章能否正常打开。

- 公众号文章要求登录、触发验证、被删除、正文无法解析或不含投递链接时，仍须按公司全称、招聘品牌名和已知别名寻找官网“加入我们/校园招聘/人才招聘”入口。
- 公司官网把招聘托管给北森、大易、Moka、飞书招聘、智联、51job 等平台时，该公司品牌化/主体可确认的 ATS 视为官方招聘系统。
- 只有官网/官方 ATS 已实际尝试后，才允许把公司标成 `访问受限`；必须记录具体受限点。公众号受限本身只影响公众号链路，不能代表官网受限。
- 只有官网岗位列表可访问并完成检查后，才允许写 `无目标岗位`。公众号没写目标关键词、公众号正文不完整或文章被删除，都不能推出“无目标岗位”。
- 每个公众号线索必须在审计台账中记录 `wechat_url`、`official_url`、`official_search_attempted`、`official_check_result`、`access_reason` 和 `next_action`。任何 `official_search_attempted=false` 的记录都属于未完成队列，本轮不得静默收口。

### 牛客入口逐企业复核（每日强制）

牛客的“校招日程”“秋招日报/速递”“校招专场”和首页会以“一键投递”方式列出企业入口。这类入口不是可选线索池，而是每日必须清空的复核队列。

每次运行必须枚举当日可见的企业入口，并对每家公司逐一检查牛客详情和公司官网/官方校招系统；公众号跳转只算发现线索，不算完成官网核实。企业名称、公告文案或入口卡片本身不命中目标关键词时也不能跳过。目标方向的职责完整岗位进入主表；其余企业必须在官网已尝试后被明确标为“已有岗位”“无目标岗位”“职责不完整”“访问受限”或“入口失效”。

将本轮结果写到 `output/nowcoder-entry-audit-current.json`。该文件是覆盖性台账，不等同于主表：它必须保留公司名、全部入口链接、入口出处、核查时间、处理结果、匹配岗位名、公众号链接、官方链接、官网是否已尝试、官网核查结果、具体受限原因和下一步。访问受限、验证码和登录限制须列为待复核，下次继续处理，绝不能静默当作无岗位；公众号受限但官网尚未尝试的记录属于“未完成”，不能计入已逐一复核。

“最多深入核实 10-15 家”的一般效率建议不适用于此队列；仅可用于牛客之外的宽泛发现来源。若当日入口很多，应优先完成所有入口企业的基础检查，后续再展开同一公司内的非目标岗位。

### 重点监控扩展

每次四路发现都要额外检查 `company-watchlist.md` 和 `config.json.priority_monitoring` 中的 2027 届校招大厂、Shopee/Sea（虾皮）以及央企/国企技术校招。优先识别正式批、提前批、SP/AIDU 和可转正实习；海外 2027 Intake 只能作为观察信号，不能替代中国岗位详情。央国企岗位应尽量回溯至官方校园招聘入口，并在记录中标记企业性质和 `is_central_state_owned`。

### 高风险高成长公司增量层

启用后，四组来源除了返回岗位候选，还要分别返回可能处于业务上升期的上市科技公司、未上市科创公司、早期技术团队和细分行业黑马。公司线索必须与岗位候选分开，按 [high-growth-company-discovery.md](high-growth-company-discovery.md) 的证据、评分、风险和反向查岗规则处理。股价、融资、媒体榜单或创始人财富只能用于发现，不得直接进入岗位主表。

## 核实层（顺序执行，仅针对本次新出现的公司）

牛客岗位按下节强制核实，不受公司是否已见、入口审计开关或 5 家上限影响。其他来源可补充核实 state 中全新出现的公司，访问其官方校园招聘页并获取权威链接，每次最多 5 家。

### 牛客岗位官网链接优先（新增与存量通用）

凡最终岗位链接来自 `nowcoder.com` 或其子域名，入表前必须按公司主体定位并实际检查其官网校园招聘页或官方 ATS。公司官网委托的北森、大易、Moka、飞书招聘、智联、51job 等系统，经官网链接或可核验官方公告确认主体后，视为官网。不能仅因页面出现公司名称就认定为官方。

按以下顺序选择 `source_url`，目标届别由 `config.json.target_grad_year` 决定（配置为 2027 时核实 27 届）：

1. **官网对应岗位**：确认当前仍可申请且届别符合，核对职责、岗位编号（如有）、城市和招聘轨道；标题不同但职责相同可匹配，只有相似标题不足以认定。优先填官网单岗详情/申请链接，记录 `official_match_status=matched_job`。
2. **官网已开放目标届别校招**：没有定位到对应单岗，但官网或官方公告明确证明目标届别招聘已启动、申请入口当前有效，填该届校招入口；有可复用筛选/职位定位链接时优先使用。记录 `official_match_status=target_campus_open`，并注明“已确认目标届别校招开放；具体岗位仍依据牛客，官网岗位未确认”。牛客岗位本身仍须满足当前有效、职责完整、届别与方向要求；校招开放不能证明某个具体岗位仍在招，也不能把日常实习标成正式校招。
3. **无可核实官方入口**：未找到对应岗位或已开放目标届别校招、只找到公司首页/往届页面、主体不明或访问受限且无其他官方证据时，继续填牛客岗位详情链接。分别记录 `not_found` / `not_open` / `access_restricted` / `subject_unconfirmed`，给出具体原因和下一步；不能把访问受限写成“官网没有岗位”。若已取得当前有效校招入口的官方证据，仅单岗详情受限，仍可按第 2 项选择校招入口。

官网明确证明同一岗位已关闭、届别过期或要求不符时，按正常失效/资格规则处理，不能用牛客旧链接掩盖该证据。同公司其他岗位关闭不等于该公司所有岗位失效。

每条牛客来源记录保留以下字段，合并、去重及后续状态更新不得丢弃：

- `discovery_url`、`discovery_platform`：原牛客岗位详情链接（保留完整参数）和发现栏目。
- `source_url`、`source_platform`：按上述优先级选择的最终投递链接及所属官方平台；回退时为牛客。
- `official_url`、`official_search_attempted`、`official_checked_at`：实际核查入口、是否实际尝试、核查时间；选择官网链接时 `official_url` 与最终 `source_url` 一致，其他佐证页面放在 `official_evidence_url`。
- `official_match_status`、`official_evidence_url`、`official_check_result`：上述匹配结论、支持结论的官网/官方公告链接、已核实届别及岗位对应关系。证据链接不能用牛客替代。
- `official_fallback_reason`：保留牛客的具体原因；选择官网时可为空。
- `verification`：面向读者说明是“官网对应岗位已核实”“仅官网目标届别校招开放”还是“保留牛客待续核”。

存量牛客记录也按此优先级复核。原牛客链接升级为同一岗位的官网链接时保留历史身份、首次发现日期及处理状态，同步当前候选、状态键、当轮新增文件（若该记录在其中）和 Excel 超链接；仅链接更新不增加新增岗位计数。官网通用入口可能承载多个不同岗位，不能按共享 URL 把它们合并。

## 明确降级 / 不作为每日默认来源

**BOSS直聘、拉勾** — 需要登录态 + CDP 才能稳定访问，反爬和账号风险较高。只有当发现层 4 个来源当天完全没有结果时，才考虑作为补充手段临时启用，不写入常规每日流程。

## 兜底原则

某个来源当天打不开、或没有相关结果，对应子 agent 应如实汇报为空（例如"该来源今日无可用目标方向校招信息"），**不要**反复重试同一种访问方式去"确认"是否真的没有。orchestrator 不应因为单一来源当天失败/为空就中断整体流程，其余来源的结果照常合并处理。

## 调用约定

每个发现层子 agent 的 prompt 必须：
- 显式包含「必须加载 web-access skill 并遵循指引」这句话。
- 用目标性措辞下达任务，把 `config.json` 里 `job_category_label`、`target_grad_year` 的实际值代入（例如"调研牛客网上有哪些{job_category_label}方向的{target_grad_year}届秋招正式岗位"），不要指定具体方法动词（不要写"用WebSearch搜索"之类），把搜索/抓取/CDP升级的路由决策留给 web-access 自己判断。
- 要求返回结构化列表，字段：公司名称、职位名称、工作城市、岗位亮点摘要（1句话）、最终投递链接（完整含参数）、来源栏目名称；牛客来源必须额外返回上节规定的原始发现链接与官网核实证据字段。
- 要求公众号或牛客入口发现公司后，无论公众号是否可访问，都必须继续检查该公司官网/官方 ATS；公众号访问失败不是该公司的终止条件。
- 对牛客链接，明确要求“先找官网对应岗位，其次核实目标届别已开放的官方校招入口，有可核实官方入口就填官网，否则保留牛客并说明原因”；不允许只在审计文件记录官网、主表却继续保留已可替换的牛客链接。
